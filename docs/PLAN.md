## 阶段 1 · 世界与光河 ✅ 已完成

**目标**：把「深空 + 星尘 + 光河粒子 + 辉光 + 涟漪 + LOD」的视觉基底立起来。这阶段不碰手势、不碰 AI、不碰音乐。

> **实际交付（2026-10-18）**
> - 深空：canvas 内绘制的球壳背景（纵向渐变 #05060f→#0a0f1f + 地平线柔光 + fbm 星云 + 暗角）——放在 canvas 内是为了让 bloom 处理整帧
> - 光河：88k 粒子，位置全部在顶点着色器里算（流动 / 弯曲 / swell / 侧摆 / 涟漪位移 / 情绪取色 / 闪烁）
> - 情绪光色：冷蓝→青白→暖金，沿时间轴形成「暖年份 / 冷年份」的段落；涟漪环也按情绪取色
> - 涟漪：4 槽位波前（抬升 + 径向推开粒子）+ 12 个柔边光环实例，点击/拖拽水面触发，另有自动涟漪
> - 拖尾：4 层「稍早时刻」采样，把点拉成光丝（`PARTICLE.trail.layers`）
> - LOD：GPU/核心数/内存/UA 判定 + 运行期 FPS 换档（带迟滞），降档只改 drawRange，关 bloom 时补偿亮度与曝光
> - 验证方式：`?capture=1` 从应用内部导出真实帧缓冲（无头截图管线在本机是坏的）
>
> **形态修正（2026-10-18）**：首版做了「地面上的河 + 消失点透视」，被否 → 改为横向蜿蜒的悬浮光带；
> 随后升级为 **3D 中空螺旋星管**（Frenet 框架 + 螺旋缠绕 + 前后纵深 + 2 个完整波浪）。
> 详见 `docs/DECISIONS.md` 第 7、9 条。另：**照片只在 L2 出现**，L0/L1 仅情绪粒子。
>
> **与计划的偏差**
> - 照片解体（`photoSpawner`）挪到阶段 3：它依赖照片导入，而导入是阶段 3 的事
> - 涟漪提前到阶段 1 做（原本排在阶段 3），因为它属于「世界」的一部分，且阶段 2 的手势需要它做反馈
> - 占位记忆数据暂未加入：光河的密度团簇（`RIVER.clusters`）已经预埋了「照片落点」的位置感

**交付物（历史计划，已由上面的实际交付替代，保留以对照）**

- `scene/Stage.ts`（改造）渲染器 + ACES tonemapping + DPR 钳制 + resize
- `scene/postfx.ts` 自建 bloom（`PALETTE.glow`），不做全屏 UnrealBloom 过重方案，先做单 pass 高斯 + 阈值
- `particles/river.ts` 光河主体：沿时间轴（`TIMELINE`）铺开的带状点云，curl noise 湍流 + 顺流位移（`PARTICLE.motion`）
- `particles/photoSpawner.ts` 单张照片 → 粒子云，`PARTICLE.dissolve` 曲线（膨胀 `burstScale` → 归流 `riverPull` → 残留 `shapeRetention`）
- `particles/color.ts` 情绪值 → 暖金/青白/冷蓝插值（`PALETTE.emotionRange`、`PARTICLE.color`）
- `shaders/river.vert.glsl` `shaders/point.frag.glsl`（圆形柔边 + 距离衰减 + twinkle）
- `ui/HoverRipple.tsx`（视觉层涟漪，暂不接手势）
- `state/placeholderMemories.ts` 占位切片数据（仅开发用，阶段 3 换成真实导入）

**实现要点**

1. 粒子用 `THREE.Points` + 自定义 `ShaderMaterial`：位置在顶点着色器里做噪声位移，CPU 只上传「基础属性 + 时间」，绝不在 JS 里逐帧遍历 15 万点。
2. 预算按 `PARTICLE.budget` 分配，超预算按 `uploadPerFrame` 分帧上传，避免首帧卡死。
3. 情绪色由 `emotion ∈ 0..1` 映射：0 → `coldBlue`，0.5 → `cyanWhite`，1 → `warmGold`，并按 `color.jitter` 抖动。
4. `PERF.degradeThresholdFps` 触发降级：粒子预算 ×`degradeRatio`，先砍星尘再砍拖尾。
5. `prefers-reduced-motion` 时（`PERF.respectReducedMotion`）：光河静止、关拖尾、保留辉光。

## 阶段 2 · 手势与输入

**目标**：把手势状态机按 `GESTURE` 全量实现，并让鼠标/键盘达到**功能等价**（不是降级版）。同时完成所有即时反馈：光标柔光拖尾、悬停高亮 + 进度环、取景框引导、丢失提示。

**交付物**

- `gesture/tracker.ts` `getUserMedia`（`VISION.camera`）+ `FilesetResolver.forVisionTasks` + `HandLandmarker.createFromOptions`，`detectForVideo` 节流到 `GESTURE.detectFps`，失败时 store 置 `gestureStatus='unavailable'`
- `gesture/features.ts` 21 点 → `HandFeature`：openness（指尖到掌心均值 / 手掌尺度，`VISION.landmarks`）、pinchDistance（4↔8）、食指位置与速度（EMA `GESTURE.smoothing`）
- `gesture/stateMachine.ts` 状态机（**本阶段核心**）：
  - `openness > 0.6` **边沿触发**放大，冷却 500ms（`GESTURE.openness`）
  - 合拢 <300ms 后张开 → **复位并继续放大，绝不缩小**（`resetMaxMs`）
  - 合拢 300–500ms → 缓冲带不动作
  - 合拢 ≥500ms → 缩小（`shrinkMinMs`）
  - 捏合 `pinchDistance < 0.05` 连续 3 帧 → 确认（`GESTURE.pinch`）
  - 张开 + 横向速度 > 1.2 屏/秒 → 拨动（仅 L0–L1，`GESTURE.swipe`）
  - 食指移动 → 悬停；停留 1.5s → 确认（`GESTURE.dwell`）
  - 合拢永不产生 click；拨动中暂停悬停；拨动中合拢立即停拨动
  - 一帧只出一个信号，冲突走 `pickDominantSignal`（`GESTURE_PRIORITY`）
- `ui/HandFrame.tsx` 半透明手形取景框 + 「把手放进来」（`UI_COPY.handFrame`），呼吸动画
- `ui/Cursor.tsx` 柔光 + 拖尾（`PALETTE.cursor`），手势/鼠标共用同一渲染
- `ui/HoverRing.tsx` 高亮 + 进度环，环满 = 停留确认（`PALETTE.hover.progressMatchesDwell`）
- `input/pointerSource.ts` `input/keyboardSource.ts` 与手势共用同一套 `GestureMachine` 接口（**关键设计**：鼠标键盘不写第二套逻辑）
- `audio/sfx.ts` 占位音效（放大上扬 / 缩小下沉 / 拨动流动 / 确认钟声，`MUSIC.sfx`），阶段 5 接入正式音源
- 手势丢失 2s → `UI_COPY.gestureLostHint`（`GESTURE.lost`）

**自测清单**

- [ ] 张开手：放大一次；手不收回再抖，**不会连发**（冷却 500ms 生效）
- [ ] 合拢 200ms 立刻张开 → 复位到全景，且**没有**缩小（这是最容易写错的一条）
- [ ] 合拢 400ms 再张开 → 什么都不发生（缓冲带）
- [ ] 合拢 800ms → 缩小一层，且持续合拢不会连续缩小
- [ ] 捏合 3 帧才确认；快速捏一下就松 → 不确认
- [ ] 合拢过程中点击光标 → 绝无点击事件（日志里无 click 信号）
- [ ] 拨动中手合拢 → 立即停止，且不回弹
- [ ] 拨动中不出现悬停高亮，进度环不涨
- [ ] 手离开画面 2s → 提示出现；手回来 → 提示消失、状态自动恢复
- [ ] 按 G 切到鼠标：滚轮=缩放、拖拽=拨动、停留=悬停、回车=确认、Esc=退回，**行为与手势一一对应**
- [ ] 单手快速抖动 / 半张手出画 → 无连环误触（连续 10s 只允许 0–1 次事件）
- [ ] 拒绝摄像头权限 → 自动进入鼠标模式并给出提示，不报错、不白屏

## 阶段 2 · 照片导入与层级系统 ✅ 已完成（鼠标/键盘版）

> **实际交付（2026-10-18）**
> - 导入：右下角「导入照片」+ 全窗口拖拽；图片解码后取平均色 → 情绪温度 → 时间轴位置（按情绪排名均匀铺开，避免冷色照片全撞一端）
> - 照片化身：**颗粒云（2600 点/张）+ 贴图平面**双层。`assemble` 0→1 时粒子从河里的散落位置被吸到照片平面上 —— 这就是「粒子重组出照片」；贴图负责近距离的可读性，并且自带边缘溶解，不会露出硬矩形
> - 三档视觉：L0 完全隐形（只看光带）/ L1 可辨认的缩略节点 / L2 占视口 0.72 的清晰照片（`PHOTO.stages`）
> - 层级相机（`scene/layerRig.ts`）：临界阻尼弹簧 + L2 锁定；在 L2 继续往里滚只有 `overshootLimit` 的过冲，随后自动回弹
> - L2 时河体退场：粒子降到 22% 不透明度、聚焦照片周围 2.6 世界单位内「清场」、星尘减半
> - 输入：滚轮 / ↑↓ / WASD / Esc；点击照片平面或缩略图即可聚焦（Enter 聚焦最近一张）
> - 手势（MediaPipe）按决策挪到阶段 3，此阶段的交互全部可用鼠标键盘完成
>
> **修掉的两个真问题**
> 1. **多次导入后"某些照片放大时不见了"**：`layoutSlots` 每次新增照片都会重排整条时间轴，
>    而照片节点只在首次创建时读取 `slot` → 旧节点的世界位置停在上一次排版上，相机却按新 slot 对焦。
>    证据：`?diag=1` 显示 store slots `[0.09,0.295,0.5,0.705,0.91]`，而三个节点的实际落点全是 0.91（重叠）。
>    修法：`PhotoField.sync()` 发现 `node.slot !== photo.slot` 就重建节点，并用当前装配度快照直接初始化（不闪）。
> 2. **L2 时照片上有白雾**：自动涟漪的光环是 `depthTest: false`，会盖在照片上。聚焦态（progress > 1.15）停掉自动涟漪。
> 3. **照片过曝**：叠加在照片上的颗粒云（加法混合）+ bloom 拾取亮部。修法：颗粒云在 L2 降到 0.12、单点强度回归 1.0，
>    贴图整体乘 `PHOTO.exposure`（0.85），让照片落在 bloom 阈值之下、颜色回来了。
> 4. **照片依然"过曝"（第二轮，用数据定位）**：
>    - 写了 `?exposureProbe=1` 量化对比，发现高画质下照片均值其实准（133 vs 源 138），
>      但**低画质档因为 LOD 的 `exposureBoost` 改了全局 `toneMappingExposure`，把照片一起推亮 +18/通道**；
>    - 且照片平面和粒子一起过了 bloom，真实照片的亮部会被拾取成光晕糊上来（缩略图上尤其明显）。
>    - 修法：① 照片平面搬到独立的 overlay 场景，在 bloom **之后**叠加，完全不参与辉光；
>      ② 曝光补偿只乘进 `river.setBrightness()`，不再动全局曝光；③ `PHOTO.exposure` 收到 0.9。
>    - 校准结果：源 (138,134,66) → 渲染 (136,134,64)，最高亮度 184 → 187，零溢出，两档一致。
> 5. **碎裂会"闪一帧全碎"**：`shatter` 由层级变化速度驱动，而跳层是瞬移（Δprogress 可能达到 2），
>    除以极小的 dt 会瞬间打满。修法：`Δprogress > 0.3` 视为瞬移、不触发碎裂。
> 6. **L2 的"贴纸感"（第三轮重构）**：照片原来是一张高不透明度贴图 → 像贴纸糊在屏幕上。改为**高斯泼溅点云**：
>    - 每张 3.6 万枚柔光斑，alpha 合成（加法会让背后蓝光永远透上来，实测蓝通道 +27）；
>    - 按 `aRadial` 做**径向凝实**：中心先实、外圈后实，波纹由内向外扩散，最外缘永远漂浮；
>    - 未凝实粒子沿河里散落方向飞散（`radial.edgeScatter`），与长河融合，没有硬边框；
>    - 贴图降到 0.14 只做辨识度兜底；
>    - 修了一个 config 替换静默失败的问题（`stages` 一直是旧值，导致两轮调参没生效）——
>      现在用 `?diag=1` 直接读**实际生效的 uniform 值**来验证。
> 7. **缩小的时候照片没有碎成粒子**：原来 L2→L1 之间 `assemble` 几乎不变（1 → 0.92），自然看不出碎裂。
>    修法：新增 `PHOTO.shatter` —— 按**层级变化速度**临时打散照片（`assemble` 下降、颗粒放大提亮、贴图淡出），
>    松手后重新聚拢。往回收时照片是真的炸成粒子飞回河里，再在节点上重新成形。

## 阶段 3 · 手势完整交互与视觉反馈 ✅ 已完成

> **实际交付（2026-10-18）**
> - **画中画**：左下角玻璃拟态小窗，摄像头画面水平镜像，21 点骨架用 `drawConnectors`/`drawLandmarks`
>   画成绿色发光连线（粗描两遍：外发光 + 细亮线），食指尖额外画青白径向光斑；上方实时状态文字
> - **状态机**（`gesture/stateMachine.ts`，纯逻辑）：严格 8 级优先级，全部计时走 `performance.now()`
> - **光标**：`ui/GestureOverlay.tsx` 用全屏 2D canvas 画柔光光标 + EMA 平滑 + 拖尾 + 悬停进度环 + 张开度弧
>   （有意不走 React，避免 60fps 重渲染）
> - **拨动**：手势横向速度 → 长河视线平移（世界单位），带惯性衰减与边界橡皮筋回弹，L2 自动回中
> - **降级**：滚轮缩放 / 拖拽漫游 / 点击进入 / 悬停高亮；摄像头被拒自动切鼠标模式；`G` 键随时强制切换
>
> **⚠️ 真机反馈后的重构（2026-10-18 第二次）**：原来的"合拢 500ms 缩小 / 合拢再张开复位 / 张开边沿放大"
> 在真机上反直觉、易卡住。已改为**连续量控制**：
> - `openness` 线性映射到层级进度 0..2（`GESTURE_CONTINUOUS`：0.3→L0、0.94→L2），
>   手张开多少，河就近多少；**彻底删除复位动作与 500ms 冷却**；
> - 捏合时**冻结缩放**（捏合要握手指，openness 会掉，不冻结就会把画面推远），松开后 320ms 解冻；
> - 手短暂飞出画面 **1 秒内保留最后的光标与缩放**，超过宽限期才判定丢失；
> - 确认聚焦后**锁定 1.3 秒**，避免张着的手立刻把照片拉回去；
> - 保留两个边沿确认：捏合、停留 1.5s。
>
> **实测（`?simMachine=1`）**：
> - 连续映射：openness `0.30→0.90` 对应进度 `0.000→1.875`，单调线性、无跳变；
> - 捏合冻结：捏合前 `1.875` → 捏合中（openness 掉到 0.55）仍是 `1.875` ✓；
> - 丢手 600ms：光标仍显示（宽限期 1000ms）✓；超过 1s 才触发 `handLost` ✓；
> - 停留 1.5s：`hover` → `dwell` @+1504ms ✓。
>
> **⚠️ 真机手型适配（2026-10-18 第三次）**：用户张开手掌时 openness 只有 0.5，够不到阈值。
> - 根因：`openness` 是「指尖到腕 / 手掌尺度」的比值，绝对值因人而异；默认区间 1.35–2.35 偏高
>   （实测该用户张开 ≈ 1.85，原公式只给 0.5）。
> - 修法 ①：默认区间收窄到 **1.22–2.02**，连续映射放宽到 **0.22–0.8**，`zoomInThreshold` 降到 **0.4**；
>   同一只手在默认区间下现在是 0.79（不再需要校准也能用）。
> - 修法 ②：**一键校准**（画中画下方按钮）：握拳 3 秒 → 张开 3 秒 → 取 20%/80% 分位作为 lo/hi →
>   存 localStorage；每个阶段有 350ms 稳定期，避免换姿势时的样本污染。
> - 修法 ③：画中画里实时显示 **openness（两位小数）+ 原始比值 + 竖条**，肉眼即可判断手型要不要校准。
>
> **校准仿真（`?simCalibration=1`，注入时钟）**：默认区间 1.22–2.02 → 握拳采到 1.24、张开采到 1.86
> → 落库 `calibrated: true`；同一只手 ratio 1.85 的 openness 从 **0.788（默认）→ 0.983（校准后）**。
>
> **UI bug 修复（2026-10-18）**：校准浮层的「关闭 / 再来一次」点不动。
> 根因：`CalibrationPanel` 挂在 `CameraPreview` 里，而该容器为了不挡画布是 `pointer-events: none`，
> 浮层作为子元素继承了它 → 整层点击穿透。
> 修法：浮层用 `createPortal` 挂到 `document.body`，并显式 `pointer-events-auto`；
> 顺带加了 `Esc` 关闭与「完成后 1.8s 自动收起」。
> 新增 `?hitTest=id1,id2` 用 `document.elementFromPoint` 验证点击可达性（本轮实测 4 个按钮全部命中自身）。
>
> **⚠️ 交互大改（2026-10-18 第四次）：无限长河 + 拨盘式焦点**
> 1. **废弃"食指点击切图"**：长河变成一台转盘。拨动改变滚动位置，**离画面正中心最近的照片自动成为焦点**
>    （虚线环常亮）；停手后先惯性滑行，再弹簧吸附，把选中的照片精准停在正中（实测吸附偏差 0.000）。
> 2. **长河改为无限长**：`riverPath` 里波形是 x 的纯函数，任意 x 成立；粒子池只覆盖相机附近的
>    `poolWidth`，着色器里加 `uScroll` 做 mod 环绕 —— 接缝发生在屏幕外（`poolWidth` 比取景宽 30%）。
> 3. **动态加载**：只给视口 ±`visibleRadius` 张照片建节点（上限 `maxNodes`），滚出视口的直接 dispose。
>    实测：10 张照片在河中间只建 7 个节点、在末端只建 4 个。
> 4. 照片位置改为 `第 i 张 x = i × spacing`（新导入自动落在右边），情绪只决定颜色不再决定位置。
> 5. 悬停降级为"只做提示"：`GESTURE.dwell.autoConfirm = false`（默认不再用停留自动进入）。
>
> **验证数据（`?scrollSim=v&demoPhotos=10`）**：初速 −6 → 落点 35.00（第 5 张，偏差 0.000）；
> 初速 −12 → 落点 63.00（第 9 张，最后一张）；初速 +4 → 落点 0.00（左端橡皮筋）。
>
> **第五轮（2026-10-18）：把"整只手拨动"和"无限长河"焊在一起**
> - **拨动 = 手掌张开（openness > 0.6）+ 横向移动**；阈值 `velocityThreshold` 0.45 屏宽/秒，横向必须主导。
> - **物理手感改成"直接映射"**：`driveSwipe()` 把每帧的手掌速度直接写成滚动速度（带一点低通），
>   而不是逐帧累加冲量 —— 后者在 30fps 下会累积成疯转。手停 → 不再调用 → 惯性衰减 → 吸附。
> - **食指不再拾取照片**：光标只做视觉引导；悬停/停留的目标恒定是"当前居中的那张"。
> - **进入方式三种**：捏合、**张开→突然握拳**（边沿 + 1.4s 冷却，握拳期间画面续锁在 L2）、手静止 1.5s。
>   停留现在要求 `|vx|,|vy| < 0.18`，手在动就不累计 —— 拨完手没放下不会误进。
>
> **仿真验证（`?simMachine=1`）**：`pinch@464ms`、`handLost@1936ms(>1s 宽限)`、
> `dwell@3968ms(手静止)`、**`手抖动悬停 1.7s → 没有 dwell`**、`fistEnter@6176ms`。
>
> **第六轮（2026-10-18）：分离「平移」与「缩放」—— 真机冲突修复**
> 真机问题：① 拨动很难触发（要求 openness>0.6，手没完全张开就无反应）② L1 想拨动结果被推到 L2
> ③ 必须把手臂伸直才"够张开"，很累。
> - **拨动放宽**：`swipe.minOpenness` 0.6 → **0.35**，只要大致朝镜头 + 横向速度主导即可。
> - **拨动优先**：拨动中（含 260ms 惯性尾）**冻结缩放**；`Stage` 再加一道闸 —— 只要 `|scrollVel|` 还在
>   或正在吸附，就完全忽略缩放输入。双保险确保"平移就是平移"。
> - **分带映射**（`progressForBand`）：L0 段 openness→[0,1]；**L1 段锁死 progress=1**（张开手绝不切层）；
>   L2 段 openness→[1,2]。层间切换全部带滞后：`commitL1At 0.94 / 220ms`、`backToL0At 0.1 / 420ms`、
>   `backToL1At 0.24 / 420ms`。
> - **L1→L2 只能靠确认**：捏合、握拳，或"张到极限并静止 4 秒"缓慢推进。停留自动进入已关闭。
> - 缩放阈值区间收到 `0.2–0.68`，舒服张手就能到顶，不用伸胳膊。
>
> **专项验证（`?simMachine=1` → bandCheck，独立机器实例）**：
> `L0 握拳 → committed L0`；`张开到顶 500ms → committed L1, progress 1.086`；
> `L1 上张开手横向拨动 600ms → committed 仍是 L1，progress **1.086 不变**`（关键）；
> `静止极限张开 2.8s → committed L2, progress 1.997`。
>
> **本轮自己引入又自己抓到的回归**：重写"有手"分支时漏掉了 `handPresent/lastSeenAt/lostEmitted` 三行，
> 导致"手离开"永不触发、光标永不显示 —— 被上面的仿真（丢手 600ms 光标应仍显示）当场发现并修复。
>
> **第七轮（2026-10-18）：极简三动作 —— 彻底删减**
> 真机反馈：手臂悬空平移太累、规则太多。按用户定义重写为**三个互斥动作**：
> 1. **扇风 = 切照片**：不做位置跟随，只认**手掌中心**（四个 MCP 均值）的瞬时横向速度，
>    超过 `flick.velocity` 就给长河一个**一次性冲量**（`impulseGain`），惯性滑行后磁吸。
> 2. **手静止 = 缩放**：手掌速度 < `stillVelocity` 持续 70ms 才允许读 openness；
>    手一动立刻冻结缩放。
> 3. **捏合 / 快速握拳（<420ms）= 确认进入**。慢慢握拳只缩小、不进入。
>
> 删除：手掌平移连续跟随、张开度阈值切层、300ms 复位、500ms 缩小、300–500 缓冲带、
> 停留自动进入、极限张开推进、`swipe.velocityThreshold` 连续驱动。
>
> **仿真验证（`?simMachine=1`）**：
> `静止张合 → progress 0.208 → 0.875`；**`扇风期间 progress 完全不变（0.875→0.875），flickEvents=1，zoomFrozen=true`**；
> `捏合 → committed L2`；`快速握拳 true / 慢速握拳 false`；`丢手 600ms 光标仍显示 → 1 次 handLost`。
>
> **第八轮（2026-10-18）：修"扇不动"**
> 真机反馈扇风很难触发。三个原因一起修：
> 1. **测速点错了**：原来测手掌中心（离腕约 6cm），手腕扇风时它移动很慢。改成
>    **四指尖 + 四掌指关节的均值**（手腕甩动时指尖扫得最快），阈值也从 1.15 降到 **0.95**。
> 2. **EMA 把峰值抹平了**：速度做过 α=0.5/0.3 的指数平滑，100ms 量级的甩动峰值直接消失。
>    改成**环形缓冲 + 60–260ms 多窗口取横向峰值**（既保留瞬时峰值，又抗掉帧）。
> 3. **冲量太小**：原来滚多远取决于一个裸系数，实测只走 1–5 个世界单位，磁吸又把你吸回原张。
>    改成**按张数算**：`photos = clamp(|v| × 1.15, 1, 3.2)`，反推初速度 = 距离 × 衰减率。
>    **`minPhotos = 1` → 只要触发就至少滚一张，绝不会"拨了没动"。**
>
> 实测（`?scrollSim=`）：速度 1.0 → 滚 1 张；1.6 → 2 张；3.0 → 3 张；磁吸偏差全部 **0.000**。
> 画中画新增 **`扇 xx`** 实时读数（超过阈值变金色），可以直接看出检测器读到了多少。
>
> **第九轮（2026-10-18）：L0 不该有焦点环 + 锁定的照片必须真的在正中**
> 1. **焦点环在 L0 也画了**：照片在 L0 还没显形（`revealAtProgress` 0.22），凭空一个黄圈很莫名其妙。
>    改成只在 `layerProgress > revealAtProgress + 0.06` 时画。实测：L0 不可见 / L1 可见。
> 2. **照片不在正中间（越往右越偏）**：两个叠加的 bug
>    - **相机横向位置被加了两次**：`composePose` 里聚焦分支已经算进 `scrollX`，外层又按滚动权重
>      加了一遍 → 相机跑到 2×scrollX。所以只有第一张（x=0）是正的，越往右偏得越多 —— 正是"边缘照片"症状。
>    - **相机对横向做了二次平滑**：滚动本身已有弹簧平滑，相机再低通一次会让照片"追不上"正中间。
>      改成横向直接跟随（纵向/纵深仍低通）。
>    - 另外打断了"自动焦点 → 写 store → 订阅吸附 → 暂停自动焦点"的反馈环（用 `autoFocusGuard` 标记），
>      并在长河停稳的瞬间强制把焦点对齐到居中那张。
>    **实测（`?diag=1&scrollTo=` 0/7/21/42/63/70）**：焦点屏幕 x 全部 **0.500**；
>    滚到 70（超出末端）时橡皮筋拉回 63，焦点仍在正中。
>
> **旧状态机仿真验证**（`?simMachine=1`，保留记录）：
> `张开900ms→zoomOpen×1`、`合拢600ms→closeHold@+528ms`、`合拢150ms→张开→reset`、
> `合拢400ms→张开→不reset、zoomOpen`、`捏合5帧→pinch×1`、`拨动→swipe连续`、
> `悬停1.7s→dwell@+1504ms`、`手离开→handLost@80ms(5帧抗抖)` —— 逐条与规格一致。
>
> **视觉验证**（`?simCursor=1&captureOverlay=1`）：光标/拖尾/进度环/骨架 canvas 全部导出确认为非空且形态正确。

## 需要你确认的 6 个开放问题

1. **复位落点**：合拢<300ms 再张开 → 复位到 **L0 全景**（当前 config 取值），还是回到「当前层级的根」（L2 里复位回 L1）？我倾向前者，语义更干净。
2. **照片导入方式**：拖拽/文件选择导入（阶段 3）是否够？还是要接系统相册 / 网络 URL / 目录批量？
3. **AI runtime**：阶段 4 是否接真实模型？如果要，用哪家（OpenAI 兼容 / DeepSeek / 本地 Ollama），key 从 `.env` 读还是运行时输入？不接的话我就把模板做到「够用但明显是本地」。
4. **音乐素材**：你提供音频文件，还是我先生成程序化音景（Web Audio 合成，无版权风险）？后者零素材依赖，但音色偏电子。
5. **手势性能基线**：目标机型是否只有 M 系列笔电 + 手机？如果要在老 Intel 机器上跑，`PARTICLE.budget` 要下调一档。
6. **L3 对话形态**：纯文字对话，还是要给「溯」做语音（TTS）？语音会显著改变节奏设计，建议先不接。
